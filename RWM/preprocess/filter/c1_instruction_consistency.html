C1 — Instruction Consistency（TODO）

C1 判断一个局部 demonstration clip 中可观察到的对象、动作、时序和 robot–environment interaction，是否与该 clip 的语言 instruction 语义一致。它是 video–language cross-modal consistency 检查，不是 S1–S5 的数值 trajectory/filter check，也不证明任务执行质量、canonical alignment 或 training readiness。

当前状态：TODO_DOCUMENTED / NOT_IMPLEMENTED。本页只记录未来独立 VLM pipeline 的边界；现在没有 C1 model invocation、per-split C1 JSON、VLM verdict、selection manifest 或 eligibility。现有 10-long run 继续保持 c1=NOT_RUN_BY_USER_REQUEST，artifact accounting 仍为每个 split 的 split.json + S1–S5 六个文件。

Qwen-RobotManip 明确描述的 C1

Qwen-RobotManip technical report 将 C1 称为 Instruction Consistency，采用三阶段 VLM pipeline：

  1. Temporal Normalization for Evaluation Units：把 long episode 分成 subtask-level segments，使每个 clip 对应一个时间局部的 action unit。
  2. Structured Reasoning-Guided Annotation：initial VLM 先分析 manipulated objects、action semantics、temporal ordering 和 agent–environment interaction，生成 intermediate analytical judgment，再给 final consistency decision；不是直接输出一个二元标签。
  3. Multi-Expert Cross-Model Adjudication：initial model 标成 non-aligned 或 ambiguous 的 clips 交给多个独立 VLM，再通过 cross-model voting 得到 final label。论文最终排除 inconsistent samples。

跨数据集 General Requirements

C1 属于 FILTER，但它消费的是 frozen video–annotation packet，而不是修改 annotation 或 canonical sidecar。未来每个 dataset 都必须先建立以下 contract。

RequirementGeneral contract
Evaluation unit优先使用 source 中有 provenance 的 subtask/segment annotation，绑定 exact [s,e)、local instruction、annotation revision 和 source identity。没有 local annotation 的 parent rows 为 NOT_APPLICABLE，不能继承相邻 instruction。
Video packet冻结 exact video member(s)、camera roles、frame↔video mapping、decode/image-processing revision、sampling/FPS/resolution 和 visibility policy。缺帧、损坏、遮挡或关键对象不可见属于 insufficient evidence，不是 semantic inconsistency。
Language packet使用当前 evaluation unit 的 local instruction；parent task、skill、自动 caption 和其他 metadata 只能作为显式记录的 context，不能替代 local label，也不能作为“视频一定一致”的证明。
Model packet绑定 model/provider/version、prompt/schema/parser、temperature/seed、retry/fallback、input ordering 和 raw-response hash。不同 evaluator 不读取前一模型的 rationale，避免把一个模型的偏差传播成所谓 multi-expert agreement。
Decision scope最小 verdict unit 是原始 annotated split。为了上下文限制可以构造完整覆盖的 evidence subclips 或 sampled packets，但 final decision 必须聚合回原 split，不能静默创建新的 training units。
Output 与 accounting保存 structured visual facts、reasoning/verdict、visibility/coverage、每个 adjudicator vote、parse/failure status、所有 reason codes、decisive reason 和 exact hashes；planned/processed/failed/missing splits 与每次 model call 必须完整 accounting。
Mutation boundaryC1 只能选择或 REVIEW，不能原地改 action_text、视频、canonical values 或 masks。若确认 annotation 错误，修订必须进入新的 annotation revision 与 provenance，再重跑 C1。

  • 当前 10-long scope 共 178 splits、69,245 annotated frames，178/178 有非空 local action_text；

官方 split 始终是最终 verdict/selection unit。极长 split 可以降采样或拆成 evidence windows，但这些 windows 必须完整 accounting 并聚合回原 split；某一窗口“没有看到动作”不能自动证明整条 instruction 不一致。

未来独立 VLM pipeline（设计 TODO，不是当前实现）

exact split video packet + local action_text
  → A. instruction-blind visual fact extraction
       objects / contact / action / order / laterality / state change / visibility
  → B. independent initial judge compares frozen facts with instruction
  → C. only non-aligned or ambiguous cases go to independent VLM adjudicators
  → frozen voting/abstain policy
  → per-split evidence JSON; selection remains a separate policy

先做 instruction-blind visual fact extraction 是本项目的设计建议，用于降低 VLM 照抄 instruction 后产生假一致；Qwen 论文只要求 structured reasoning，没有公开这一具体拆分。

未来建议的 evidence labels 至少区分：

  • CONSISTENT：可见证据与 local instruction 相符；它仍不自动等于 KEEP。
  • INCONSISTENT：可见证据明确与 object/action/order/interaction 等关键语义冲突。
  • AMBIGUOUS：证据或 evaluator 意见不能得到稳定结论。
  • INSUFFICIENT_EVIDENCE：关键内容不可见、clip 不完整或证据量不足。
  • PIPELINE_FAILED：decode/model/parser/accounting 失败；必须与 semantic verdict 分开。

仍需冻结的语义边界：“视频行为与 instruction 对应”不应未经讨论就等同于“任务成功完成”。例如机器人执行了正确 pick 动作但抓取失败，是否属于 C1 inconsistent，论文没有给出足够细则。本项目应把 semantic consistency 与 execution outcome 分栏标注，再通过人工 calibration 决定 language-conditioned loss 如何消费。

未来 selection 边界

  • 首轮 VLM pilot 必须为 evidence-only，selection_effect=NONE；先验证 prompts、visibility、模型一致性和人工 gold-set precision/recall。
  • 只有在 model/prompt/view/sampling/voting policy 和 held-out audit gates 全部冻结后，cross-model consensus INCONSISTENT 才可以对该 split + named language-conditioned loss 产生 DROP/ineligible；不默认删除整个 parent。
  • AMBIGUOUS、INSUFFICIENT_EVIDENCE 和 pipeline failure 应为 REVIEW 或该 language loss 不可用，不能冒充 confirmed mismatch。
  • CONSISTENT 只通过 C1；仍须满足 exact ALIGN receipt、S*/其他 C*、required fields 和 window policy。它不提升 alignment status 或 training_ready。
  • 不消费 language 的 video-only loss 可使用独立 eligibility；C1 decision 不能自动污染所有训练用途。
