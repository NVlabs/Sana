# SoL-Refiner for MiniMax-H3

Refine an H3-generated video with a single conditional denoising step. The
inference runtime loads an **offline-merged model**: it does not load an adapter,
inject LoRA layers or merge weights during inference.

[Project page](https://nvlabs.github.io/Sana/Sol-Refiner/) · [All variants](../)

## Status

This is an initial integration for review. The merged transformer has been
produced and checked against the original implementation on H100. The standalone
Diffusers transformer conversion and forward path have been exercised. A complete
Diffusers model package, public download location, and end-to-end encoder/decoder
video validation are not yet provided. Do not treat the transformer-only export
as a complete pipeline directory.

## Implementation

`infer.py` is a small argparse entry point, following the standalone inference
layout used by the SoL-Engine model directories. `sol_refiner_h3/pipeline.py`
contains the H3 refinement orchestration and directly reuses:

- `LTX2ConditionPipeline` for prompt encoding and latent packing;
- `AutoencoderKLLTX2Video` and `LTX2LatentUpsamplePipeline` for video conditioning;
- `LTX2VideoTransformer3DModel` for the denoiser;
- `FlowMatchEulerDiscreteScheduler` for the single Euler step;
- `LTX2VideoDiffusionDecodePipeline` for the LTX-2.5 diffusion decoder;
- Diffusers model loading, CPU offload, random tensor generation and video export.

The custom logic specifies the H3 one-step schedule, video-only execution,
conditioning geometry, and output crop. It does not vendor a transformer, VAE,
attention implementation or research-training package. The upstream audiovisual
transformer retains its audio parameters for checkpoint compatibility; a dummy
audio token is used and cross-modality attention is disabled. Output is video-only.

## Installation

Use a CUDA-compatible PyTorch environment:

```bash
pip install -r requirements.txt
```

The Diffusers revision is pinned because LTX-2.5 diffusion-decoder APIs are newer
than the APIs in some installed Diffusers releases. Decoder backend dependencies
must match the selected PyTorch/CUDA installation.

## Pretrained model format

`--model` accepts a local Diffusers pipeline directory or a published Hub model
ID. A complete model package must contain:

```text
model_index.json
transformer/         # premerged H3 weights, config and safetensors shards
vae/                 # compatible LTX video encoder and latent statistics
latent_upsampler/
diffusion_decoder/
scheduler/           # FlowMatchEulerDiscreteScheduler: shift=1, dynamic shifting off
text_encoder/
tokenizer/
connectors/
```

The release is one merged model, possibly stored in standard safetensors shards.
The end user does not need the training adapter or a merge command. No placeholder
Hub ID is presented as an available download.

## Refine an H3 video

Once the complete model package is available:

```bash
python infer.py \
  --model /path/to/merged-sol-refiner-h3 \
  --input /path/to/h3-video.mp4 \
  --prompt 'A snow leopard walks along a snowy mountain ridge.' \
  --output outputs/refined.mp4 \
  --width 1920 --height 1080 \
  --seed 303000 --decoder-seed 303000
```

The default denoising sigma is `0.9093750119`, followed by zero. CFG is disabled.
Diffusers prompt AdaLN uses the **scaled timestep** (`sigma * 1000`), while the
Euler scheduler uses the corresponding unscaled sigma interval.

The input must have a valid frame rate. Its temporal length is truncated to
`8k + 1` frames: a 124-frame H3 video yields 121 frames. A 1920×1080 output uses a
1920×1088 internal canvas, then crops four pixels from the top and bottom.
The encoder uses the posterior mode. Denoising and diffusion-decoder noise have
explicit seeds. Audio is not copied or generated by this entry point.

## H3 generation integration

The H3 refiner is also the second stage of a text → H3 → refined-video workflow.
Generate the low-resolution video with the selected upstream H3 implementation,
then call the same `infer.py` entry point. Keep the upstream generator's model and
settings explicit; the H3-specific reference configuration used official H3 with
the LightX2V four-step 544p generator. The independent SoL-H3 generator is a
separate implementation and should not be silently substituted when comparing
reference outputs.

This PR does not introduce a new H3 generator or claim a validated combined
text-to-video launcher. See [SoL-H3](../../minimax_h3/Sol-H3/) for the existing
SoL-Engine generator entry.

## Validation

Run the lightweight pipeline-contract tests:

```bash
python -m unittest discover -s tests -v
```

See [VALIDATION.md](VALIDATION.md) for the measured checkpoint and backend checks,
including the distinction between low-precision numerical differences and exact
weight equivalence. Full pixel-output integration remains a separate release gate.

## Maintainer packaging

`tools/package_model.py` assembles a compatible Diffusers base package and the
already-fused transformer into the single directory expected by `infer.py`:

```bash
python tools/package_model.py \
  --base /path/to/ltx25-diffusers-components \
  --transformer /path/to/premerged-transformer \
  --output /path/to/merged-sol-refiner-h3
```

This is a maintainer-side packaging step, not a user-side LoRA merge. It requires
an existing compatible Diffusers base package, including the LTX-2.5 diffusion
decoder. It does not convert a raw upstream monolithic checkpoint or upload files.
Run large model packaging on a compute host with enough memory.
