# Sol-H3 on one NVIDIA RTX 5090

Use `--offload cpu` on Linux x86_64 with one visible SM120 GPU. This profile
keeps the released model checkpoints, W8A8 H3 draft, VSA/cuDNN BSA attention,
learned H3 ×2 upscaler, latent adapter, fixed generic AV cache, three BF16 LTX
updates with Triton Sol attention, and original Conv decoder.

H3 body blocks, including nonpersistent FP8 buffers, reside on CPU between
forwards. Only one body block is transferred at a time. LTX uses its pinned
source's CPU streaming builder. The upscaler, adapter, audio encoder and video
decoder are placed on GPU for their active phases. Qwen is loaded for each
request and closed before H3 executes. The two video stages execute serially.
The default `--offload none` retains the resident Spark behavior.

```text
fresh NVFP4 Qwen → H3 672×384, 4 updates → H3 latent upscaler ×2
                → H3-to-LTX adapter → LTX, 3 updates → Conv VAE + original H3 audio
```

The final output is **1344 × 768, 121 frames at 24 FPS**, with stereo AAC.
H3 video decoding is bypassed; the two stages exchange normalized H3 latents
and original PCM through a local CPU tensor file.

## Prepare

Run from `models/minimax_h3/Sol-H3-Spark` in the Sol-Engine checkout. Reuse the
pinned [sources](../configs/dependencies.json), [checkpoints](../configs/checkpoints.json)
and generic refinement-context cache from the Spark package. Download missing
weights using [setup step 1](setup.md#1-download-weights); add the offline
weights only when the context cache must be built.

Use native Linux x86_64 interpreters for this profile. The validated deployment
shares one environment between H3 and Qwen and uses a separate LTX environment.
The Spark Qwen container and aarch64 package inventories describe a different
platform; the [observed 5090 versions](#environment-integration-checked-during-this-port)
below identify the reused environments.

Once those environments and weights are available, resolve their paths:

```bash
python prepare.py --fetch-sources \
  --python-stage1 /absolute/h3-env/bin/python \
  --python-qwen /absolute/h3-env/bin/python \
  --python-stage2 /absolute/ltx-env/bin/python \
  --prompt-cache /absolute/fixed-prompt.pt \
  --paths existing-paths.json --output paths-5090.json
```

`existing-paths.json` contains overrides for existing checkpoints or dependency
directories; omit `--paths` when using the default locations. For an external
CuTe installation, the tested override is:

```json
{
  "stage1_dependencies": "/absolute/cute-env/lib/python3.12/site-packages/nvidia_cutlass_dsl/dsl_packages"
}
```

Use the actual installed directory, as explained below. `prepare.py` fetches
missing pinned sources and applies the declared FastVideo loader patch; it
does not install the Python environments. To create a missing context cache,
add `--cache-pending`, then follow [setup step 4](setup.md#4-build-the-generic-prompt-cache-once).

## Run

Select a numeric GPU index: the pinned FastVideo runtime parses
`CUDA_VISIBLE_DEVICES` as an integer and cannot use a UUID there.

```bash
CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=0 \
python infer.py --paths paths-5090.json --offload cpu \
  --prompt "A red fox walks through a sunlit meadow. A steady wide shot follows its movement. overall_soundscape: Soft wind and rustling grass." \
  --seed 42 --output-dir outputs/fox-5090
```

The command runs a full warmup, then the formal request. `results.json` measures
the formal request continuously through the completed MP4, including Qwen
startup, CPU/GPU transfer and muxing. Cold video-model loading and the full
warmup are reported separately. Every output directory must be new.

For a batch, replace `--prompt` with `--prompts examples/prompts.jsonl`.
H3 and LTX sessions are reused; Qwen is created and closed for each request.
The equivalent Python selection is:

```python
from runtime.config import load_paths
from runtime.pipeline import Pipeline

pipeline = Pipeline(load_paths("paths-5090.json"), "outputs/batch-5090",
                    offload_mode="cpu")
```

Use the same `start`, `generate`, `finish` and `close` lifecycle as the Spark
pipeline. E2E covers the synchronous pipeline request through MP4 completion;
HTTP transport, an external queue and service cold start were not benchmarked.

## Environment integration checked during this port

The test workstation has two RTX 5090 cards; only physical GPU 0 is exposed to
this run. Each card reports 32607 MiB, driver 580.173.02. Host RAM is 188 GiB.
This is the test system, not a measured minimum RAM requirement.

The port reuses existing installations and fully hash-verified checkpoints.
It does not establish a fresh-install lockfile. Stage1/Qwen use a task-local
Python 3.12 environment with Torch 2.12.0+cu130 and Triton 3.7.0; Stage2 uses an
existing Python 3.13 environment with Torch 2.13.0+cu132 and Triton 3.7.1,
while importing the release's pinned LTX source through `ltx_root`.

When reusing pure-Python packages from another environment, its `.pth` files
are not automatically executed. For this CuTe 4.6.0 installation,
`stage1_dependencies` must point to the existing
`site-packages/nvidia_cutlass_dsl/dsl_packages` directory. Do not put the other
environment's entire site-packages directory ahead of the selected Torch.
Other installed CuTe versions may use a different directory; inspect the
actual distribution's `.pth` file. The tested additional packages are
`fastvideo-kernel==0.3.5`, `comfy-kitchen==0.2.26`, `comfy-aimdo==0.4.11`,
`remote-pdb==2.1.0`, `ftfy==6.3.1`, `omegaconf==2.3.1`, `av==18.1.0`
and `imageio-ffmpeg==0.6.0`.

## Validation

The CPU suite passed 66 tests. An explicit small GPU check passed Triton JIT,
exact eager/compiled offload parity against the corresponding resident
execution, FP8 buffer migration, construction-time mutation and exception
cleanup. It observed at most one active H3 body block. Run this check with the
Stage1 Python and the same source/dependency paths as the Stage1 worker:

```bash
CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=0 python - <<'PY'
import subprocess
from runtime.config import PACKAGE, load_paths
from runtime.pipeline import worker_environment

paths = load_paths("paths-5090.json")
subprocess.run(
    [paths["stage1_python"], str(PACKAGE / "tests/check_offload_gpu.py")],
    cwd=PACKAGE, env=worker_environment("stage1", paths), check=True,
)
PY
```
