Egocentric Annotation

这是按 VITRA 论文描述独立实现的 calibrated egocentric RGB annotation pipeline。主 candidate pilot 是 Egocentric-10K；calibrated EgoDex episode 18 的 raw/refit method-L2 数值报告与可视化也已完成，但仍是 REVIEW。不读取 HumanNet action30，也不再使用旧的 VGGT/WiLoR prototype。

Claim boundary：VITRA 仓库公开了 hand reconstruction utility 和最终 metadata schema，但没有发布完整 corpus labeling 与 modified MegaSAM glue code。这里的实现不是官方 annotation code。任何 model artifact 成功都不自动升级为 alignment PASS、canonical action 或 training-ready。

VITRA 公开的手部处理

以下只记录 VITRA 论文、pinned 官方仓库 VITRA@b355172 和该 checkout 的 code submodule YuDeng/HaWoR@891ca88 能直接支持的结论；没有把本仓库的后处理倒推成 VITRA 方法。VITRA README 指向 ThunderVVV 的 HaWoR 项目/权重分发，但那不是这里 pinned code submodule 的 remote，二者 provenance 分开记录。

一句话结论：VITRA 论文与 released hand helper 没有描述或显示用 MoGe-2 scene depth 直接拟合 wrist/hand Z。公开流程是用 HaWoR/MANO 从 RGB + focal/intrinsics 解出 camera-space 手姿和 wrist translation，用 MoGe-2 + modified MegaSAM 恢复 metric camera trajectory，再通过 T_W_H[t] = T_W_C[t] @ T_C_H[t] 合到同一 world gauge。因为完整 corpus glue 未公开，我们只能确认公开路径没有 direct hand-depth fit；手部 metric placement 与 camera metric trajectory 仍是两个必须分别验证的 claim。

逐阶段过程：VITRA 做了什么

阶段VITRA 公开证据支持的过程本项目对应规则
1. RGB / camera 输入先根据 background optical flow 判断 static / moving camera。Moving 路径用 DroidCalib；static 路径先用 DeepCalib，在 distortion 很小时再用 MoGe-2 得到最终 pinhole focal。显著畸变 source 必须 undistort 到 pinhole working view；低畸变 source 才可保留 identity working view。手部和相机分支使用同一份 working RGB 及与之对应的 focal/camera model。每个 source adapter 冻结 static/moving 判定、RGB member、decode/crop/resize/undistort 链和更新后的 K；数值绑定不等于 physical camera 已验证。本项目使用 official calibration 或 fixed-K 的路径是 source-specific adaptation，不能写成 VITRA 的统一输入实现。

3. HaWoR temporal handRaw track identity 在多数投票后已丢失；同侧 tracklets 先 merge/sort，再按时间连续性切成 merged-side chunks。每帧先生成 256×256 square crop，backbone 实际读取中央 256×192；左手先水平翻转，模型内再恢复 pred_cam tx 与 crop center。Inference 按不重叠 16-frame block 运行，尾块复制末帧补齐后再 trim。输出 root orientation、15 个 MANO local rotations、逐帧 shape beta 和 pred_cam=[s,tx,ty]；learned missing-motion infiller 不采用。缺手、不连续 track 和 invalid inference 保持 mask，不补几何、不跨 gap 平滑。Source-K 与候选 focal 只消费同一份 hash-bound effective ledger；raw ledger、raw/effective audits、resolution rows/summary 同时绑定。Short run 与 handoff-boundary mask 形成真实 gap，HaWoR 和后续 smoothing/motion 都不能桥接。
4. MANO camera-space 解码由 crop 参数和 focal 恢复 full-frame MANO model translation q，再用 wrist_C=j0_local+q 得到真正 wrist。Upstream HaWoR 对 left root 和 articulated pose 都做 Y/Z flip；released VITRA helper 只显式处理 root，后续对 MANO_RIGHT 局部几何做一次 X reflection。完整 corpus 的 left-pose glue 没有公开。q 不能当 wrist；左手 reflection 只做一次。我们的 adapter 补齐 upstream articulated-pose flip 并做数值对照。原始 HaWoR 是 baseline；mean-beta / projection-preserving translation refit 是我们的 extension。
5. Scene depth / cameraMoGe-2 提供场景 metric-depth prior，modified MegaSAM 恢复 metric-scale camera trajectory。Camera 与 hand translation 是分别估计的，且没有公开的 direct hand-Z/depth fit；但两者共享 working RGB 与 focal/intrinsics，不能称为完全独立输入。MoGe meter scale 和 MegaSAM scale-equivariance 要单独审计；它们通过不代表 HaWoR wrist Z 或 hand metric placement 已通过。
6. World fusionRelease metadata 的 episode_info['extrinsics'] 是 World→Camera。在本项目列向量记号中先取逆得到 T_W_C，再用 T_W_H[t] = T_W_C[t] @ T_C_H[t] 把 camera-space wrist/hand 放入 episode world；T_C_H 是本项目对 HaWoR/MANO camera-space hand pose 的命名，不是 release field。必须先在 unsmoothed pose 检测 wrist/root/finger 异常，再仅在 clean contiguous spans 内平滑。公开 release 只能支持 World→Camera 的方向语义；当前“首帧相机 gauge、非 gravity frame”是本项目 MegaSAM candidate 的明确实现，不写成 VITRA 未公开的 world-construction 事实。
7. Long video / segmentation长视频以重叠的 20-second chunks 处理后重组；先对 world-space 3D wrist trajectory 做 Gaussian filter，再计算 speed，左右手分别以居中 0.5-second 窗口的局部极小值作为 atomic-action cut points。重叠区必须有 identity/SE(3) 一致性 gate；分段参数是我们的版本化 policy，不能用平滑掩盖上游 gap。
8. 保存/下游Episode 保存 intrinsics 和 World→Camera extrinsics；每侧保存一组 10D beta、camera/world wrist orientation、15 个 local rotations、world wrist translation、camera/world joints 和 kept_frames。Helper 只输出逐帧 beta，公开代码没有给出 corpus annotation 如何 consolidation 成一组 beta。Loader 的 122D state / 102D action 是 human 中间表征，之后再 pad 到 unified state212/action192。我们不猜 VITRA 未发布的 beta consolidation，也不直接把 122D/102D 写成 Robot80；先由 metric 21-keypoint/MANO geometry 构造 canonical virtual gripper，再 pack state80[t] 与 incoming motion80[t]。

公开参数边界与质量边界：论文只说明 modified MegaSAM 将原 DepthAnything/UniDepth priors 替换为 direct MoGe-2，并用前序 focal 初始化 intrinsics；没有发布完整 objective、BA schedule、spline/outlier threshold 或 20-second overlap recomposition 参数。因此本项目的 disparity-gauge projection、scale-equivariance gate、mean-beta/refit 和具体 smoothing policy 都是项目实现，不是 VITRA 论文事实。官方 release 的 data/data.md 还明确说明 metadata 会继续更新，并称其当前版本经人工抽查约有 90% annotation accuracy；这是官方自报的 corpus-level 估计，不是我们对任一 episode、手部 metric placement 或 L0–L3 的验证。

HaWoR 从 crop 到 camera-space wrist 的精确语义

检测框先转成正方形 crop，inference 再乘 1.2 dilation。令 crop 中心为 (cx,cy)、边长为 b=1.2·max(box_w,box_h)、整图中心为 (c0x,c0y)、输入 focal 为 f，HaWoR 预测弱透视参数 [s,tx,ty]，再恢复 full-frame MANO model translation：

qx = tx + 2 * (cx - c0x) / (b * s)
qy = ty + 2 * (cy - c0y) / (b * s)
qz = 2 * f / (b * s)

j0 = MANO_RIGHT(...).joints[0]
wrist_C = j0 + q
vertices_C = R_root @ (vertices_local - j0) + wrist_C

q 不是 wrist。官方 VITRA helper 的 transl_new = wrist + transl 正是在做 j0+q；我们的 decoder 与该公式逐点对照，frame 0 的 vertices/joints 最大差为 2.98e-8 m。典型 j0 的 X 偏移约为左右 −105/+105 mm，把 q 直接当 wrist 会造成约 10 cm 的 X 硬偏移。

Focal 不是只在最后缩放 Z：f 一方面直接进入 qz，另一方面还进入 CLIFF bbox feature，进而改变网络预测的 s/tx/ty。因此，固定现有 pred_cam 后缩放 qz 只能做 CPU analytic diagnostic；可信的 focal A/B 必须固定 RGB、box、track 和 frame rows，完整重跑 HaWoR。

问题VITRA 公开证据支持的答案
手部使用什么 K？论文的 moving-camera 路径使用 DroidCalib；static-camera 路径使用 DeepCalib，并在低畸变时用 MoGe-2 focal；这些估计路径假设 centered principal point 与 fx=fy。EgoExo4D release 使用 official Project Aria calibration。Released inference hand-reconstruction utility 对 1 个或多个输入 frame 逐帧用 MoGe 估 FoV，取中位数后传给 HaWoR。本项目 Ego10K adaptation 使用 official fisheye calibration rectification 后的固定 K_rect；这是项目 adaptation，不应写成 VITRA 原实现。
MoGe-2 是否把手拉到 scene depth？没有公开这一步。手部 camera-space translation 来自 HaWoR/MANO；MoGe-2 用于 FoV/focal 辅助以及 modified MegaSAM 的 camera metric-depth prior。论文和 released hand utility 都没有用 MoGe depth 拟合或替换 hand Z。
transl_new = wrist + transl 是什么？这是把 HaWoR 的 MANO model translation q 转成真正 wrist translation 的语义修正，不是 hand/scene depth alignment。
左手怎样处理？HaWoR 上游对 left root 与 articulated pose 的 axis-angle Y/Z 做 handedness flip；随后用 MANO_RIGHT 生成局部几何，并在 VITRA helper 中对左手局部 X 做一次 reflection。我们的 adapter 补齐了 helper 漏掉的 articulated-pose flip，并与 released MANO decode 数值对齐。左右手共享 camera-Z bias 是否存在属于下面的 EgoDex diagnostic，不由这条 upstream 语义本身证明。
世界坐标怎样得到？HaWoR/MANO 给出 camera-space hand pose；release camera extrinsics 是 World→Camera，本项目取逆为 T_W_C 后再组合 T_W_H[t]=T_W_C[t]@T_C_H[t]。VITRA 再做 world-space smoothing、outlier removal、overlap recomposition 和 wrist-speed segmentation。
最终保存什么？Episode 保存 intrinsics 与 World→Camera extrinsics。每侧保存 MANO_RIGHT 的一组 beta、camera/world wrist orientation、15 个局部 MANO joint rotations、world wrist translation、camera/world 21 joints 和 kept_frames；transl_camspace 标成 deprecated。逐帧 beta 如何聚合成一组没有在公开 annotation glue 中给出。
手部 state/action 怎样表示？State 每手是当前 wrist translation/orientation + 15 个 local-joint Euler（51D），再加一组 10D beta，双手 122D。官方 human_pretrain.json 用 use_rel=false，但 action 仍是 start-indexed t→t+1：每手保存 relative wrist translation、relative wrist rotation，以及 target t+1 的 absolute 15-joint local Euler，共 51D；双手 102D。它们随后 pad 到 state212/action192，且与本项目 target-indexed incoming motion80[t] 不是同一个时间 schema。

重要限制：VITRA 组合分别估计的 HaWoR camera-space hand 与 MoGe-2/MegaSAM camera trajectory；二者共享 working RGB 与 focal/intrinsics，但公开材料没有 direct hand-Z/depth fit，也没有证明 metric scale 天然一致。World-space smoothing、outlier removal 和大规模训练容忍噪声不能代替这个证明。因此我们不把“MANO 贴到 MoGe depth”加入 canonical pipeline：MegaSAM camera metric scale 和 HaWoR hand metric placement 是两个分开的验证 claim，后者仍为 REVIEW，不能因为“follow VITRA”而升级为 PASS。
