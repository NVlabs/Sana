04
How it fits on one Spark

The “black magic”

The two-stage pipeline is appealing, but a single DGX Spark cannot keep complete MiniMax-H3 and LTX-2.5 stacks resident—even with low-bit quantization.
We address this with two targeted changes. (1) A trained VAE Adapter maps H3 latents directly into LTX space, removing the intermediate pixel decode/re-encode and both inter-stage VAE components. (2) For Stage 2, the low-resolution latent is already a strong condition, so a cached general prompt removes runtime Gemma loading and inference. Additional optimizations are detailed below.

Transfer latents, not pixels

A learned VAE latent adapter maps the upscaled H3 latent directly into LTX space. Skip the intermediate H3 video decode and LTX video re-encode: neither inter-stage video VAE is needed. Decode only the final refined video with the official Conv VAE.

Cache the prompt

The draft latent already gives the refiner a strong visual prior. A generic prompt can therefore guide detail refinement across different scenes. Encode it once through Gemma and its connector, then cache the features to omit both from the runtime. Qwen still encodes each new Stage1 prompt.

Keep the runtime resident

NVFP4 Qwen and an FP8 H3 DiT shrink the weight footprint. Combined with latent-only transfer and cached refinement context, this leaves room for Qwen, both video stages and the final Conv VAE to stay resident on one Spark—ready for the next request.

Keep attention sparse

Stage1 uses official 90%-sparse VSA routing with a cuDNN BSA backend, fused merge and regional compilation. Stage2 uses Triton Sol-Attn across the three refiner updates.

Decode in the layout the VAE wants

A direct NHWC shuffle removes a redundant layout conversion. Keep the official Conv VAE and its original tile sizes. No tiny preview decoder.

Finish the actual file sooner

Write frames in 16-frame chunks and shorten completion polling. Count the final H.264 encode and audio mux in E2E—not just the last model forward.

Cached refiner prompt “4K, refined, high quality, cinematic detail, clean textures, natural motion.”
Stage1 still encodes each new prompt. Only Stage2’s post-Gemma / post-connector features are shared.
