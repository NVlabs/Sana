01 · Why

Video prediction makes world action models slow, and most of them cannot remember.

World action models (WAMs) leverage the world knowledge of video generation models to improve action generation. Two problems keep them from serving as the low-level policy that must run stably on edge devices.

Prediction overhead

0.6 sper request for our 4.5B model on an RTX 5090, without optimization
< 0.1 sfor π0.5, a vision-language-action model

Besides the actions, each action chunk requires denoising the far more numerous video tokens over several steps. A synchronous robot stands still during each request.

No long-term memory

30%on the Shell Game for SANA-Robot-base, which sees only the current observation: no better than chance
75%for SANA-Robot-AR, with the hybrid memory

Many manipulation tasks depend on information that is no longer visible, such as the number of completed steps or the position of an occluded object. Existing WAMs either act from the current observation alone or keep only a few sparsely sampled past frames, which miss most of the episode and add to the latency as the memory grows.

02 · Method

One hybrid transformer, three core designs.

SANA-Robot is a hybrid linear diffusion transformer trained from Sana-Video 2. It stacks 8 blocks, each with three Gated DeltaNet (GDN) layers followed by one softmax attention layer. A GDN layer compresses the past into a fixed-size recurrent state, so its cost does not grow with the context. A softmax layer attends to every token exactly, at a cost that grows with the context.

1

Hybrid memory at constant cost

Attention is causal across action chunks, so each chunk reads the past but never the future. The softmax layers attend to the first frame and to a sliding window over the last few chunks, through which information propagates chunk by chunk. The GDN layers absorb every past chunk into their fixed-size state and keep a memory of the whole episode. Each chunk is written into the memory once, so every action chunk has the same cost.

Fine-grained, chunk-level

Each chunk stores the video latent of its full span of 32 control steps, so the memory keeps every position the target cup passes through in the Shell Game, which sparsely sampled frames may miss.

Read, but never written

The targets read the current observation, but the observation does not read them and is not written into the memory. With bidirectional attention the policy takes a shortcut through the current frame and ignores the memory (9.1% on the memory tasks, against 48.8%).

The predicted video is the bridge

The actions barely read the history directly. The video predicted for the current chunk reads the history, and the actions read this video, which is also why the memory stores only video latents.

2

A unified world action model

All three modes share one token sequence of multi-view video, proprioception and actions, and differ only in which tokens are clean conditions and which are noised targets. One network thus learns all three roles from the same data: 19.4K hours from 23 datasets of robots, handheld grippers, simulation and human video.

3

Full-stack infrastructure for memory

The memory changes both training and deployment, and the infrastructure of SANA-Robot is designed around it.

Training

Whole episodes, without padding

The memory must be learned on whole episodes, whose lengths vary widely. Multimodal sequence packing with task-balanced ordering trains on whole episodes without padding and with a stable task mix in every step. Balanced and shuffled data loading further mixes many datasets in every step.

Deployment

Memory RTC and a 5.3× faster request

Memory RTC extends real-time chunking to a policy with memory by keeping one memory per execution phase, so that every request reads a memory laid out as in training. Fused kernels, CUDA graphs, prefix caching and low-bit GEMMs reduce the latency by 5.3× to 115 ms per action chunk on an RTX 5090. See it on the robot ↓

04 · Real time

115 ms per action chunk, and 30 Hz closed-loop control.

Real-time closed-loop control requires the robot to run stably at its control frequency, 30 Hz in our deployment, without any idle time. The pipeline must be asynchronous, since in synchronous execution the robot idles during every request, and inference must be fast, so that each chunk is planned from a more recent observation.

Why asynchronous execution keeps 30 Hz

Asynchronous execution with BF16 GEMMs and d = 8: the request is issued when 8 actions of the current chunk remain and runs while the robot executes them.

Low-bit inference keeps the success

FP8 and NVFP4 GEMMs quantize the weights and activations of the backbone to 8 and 4 bits, and cut the latency on RTX PRO 6000 by 20% and 30% over BF16.

Asynchronous execution with memory: direct RTC against memory RTC

In training, a chunk that starts at step t reads memory chunks of C = 32 steps that end at t, t − C, t − 2C and so on. In asynchronous execution, consecutive requests are only C − d steps apart. A single memory can then serve all requests only by breaking this chunk structure. Memory RTC instead keeps one memory per phase φ = t mod C, and each request reads the memory of its own phase.

Asynchronous delay d (actions dropped per chunk)

The animation runs along the control steps: every window of observed video is written into a memory once, and each request reads while the robot keeps moving. Drag across the chart to scrub, or change d. The error is the open-loop end-effector position error of asynchronous execution relative to synchronous execution (C = 32), on 70 RoboDojo episodes. Memory RTC trades one copy of the memory per phase for exact training-time memories, without recomputing the history at any request.

Optimized: kernel fusion, CUDA graphs and prefix caching in BF16. Under the real-time condition, a 30 Hz control loop is met with d = 8 on RTX PRO 6000 and RTX 5090, and with d = 16 on Jetson Thor.

05 · World simulator

The same network is also a world simulator.

In the FDM mode, SANA-Robot predicts the future video caused by given actions. A policy reads the generated observation and proposes the next action chunk, the simulator renders its visual consequences, and the loop repeats entirely in imagination.
