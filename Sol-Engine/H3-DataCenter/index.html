Long-context audio-video generation

03 · Full-Opt Recipe

Shared model policy, hardware-native attention

The model-level decisions are identical on both systems. Only the sparse-attention kernel is specialized for the target GPU generation.

Shared policy

First 10 steps and first two layers stay dense. Sol-Attn uses tau=1.0, no token reordering, and an exact 951-token multimodal prefix sink.

H100

The SM90 path uses a CuTe sparse-attention backend while retaining the same online routing and exact prefix behavior.

A100

The SM80 path uses a portable Triton backend, preserving the policy and distributed execution without requiring Hopper-only instructions.

04 · Reproduce

Run the released full-opt candidate

From the Sol Engine repository root, choose the manifest matching the allocated GPU node.

4× H100

python scripts/launch_candidate.py \
  candidates/minimax_h3_h100_fullopt_exact.toml \
  --mode sbatch --confirm-submit

4× A100

python scripts/launch_candidate.py \
  candidates/minimax_h3_a100_fullopt_exact.toml \
  --mode sbatch --confirm-submit
