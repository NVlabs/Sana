    Sol-Attn¶

    Paper · Code

    Sol-Attn is a training-free sparse attention method for accelerating image and video generation. It performs dynamic block routing during online softmax and reuses proxy scores to approximate unselected blocks, avoiding a materialized routing map while preserving visual quality.

    How it works¶

    Sol-Attn combines routing, sparse computation, and approximation correction in one online-softmax pass:

    1. it computes a lightweight proxy score for each key/value block;
    2. blocks that pass the on-the-fly threshold are evaluated exactly;
    3. unselected blocks reuse their proxy scores to approximate their contribution instead of being discarded.

    This produces a dynamic block budget without materializing a full routing map.

    Kernel support¶

    GPU Architecture Execution
    NVIDIA H100 SM90 CuTe DSL, including split-KV execution
    NVIDIA B200 SM100 CuTe DSL

    The released kernels are forward-only and require contiguous BF16 Q/K/V tensors in BTHD layout with head dimension 128.

    Requirements¶

    • Python ≥ 3.10
    • PyTorch ≥ 2.10
    • CUDA ≥ 12.8
    • Triton ≥ 3.6
    • NVIDIA CuTe DSL / CUTLASS Python ≥ 4.5
    • cuda-python

    Install the package from the Sol-Engine repository root:

    python -m pip install -e techniques/sparse_backends

    Core API¶

    from sol_attn import sol_attn

out = sol_attn(
    q,  # Queries: contiguous BF16 CUDA tensor of shape [B, T, H, 128].
    k,  # Keys: contiguous BF16 CUDA tensor of shape [B, T, H, 128].
    v,  # Values: contiguous BF16 CUDA tensor of shape [B, T, H, 128].
    tau=1.0,  # Threshold coefficient; larger values route fewer KV blocks exactly.
    thresh_type="exact",  # Use full covariance for the routing threshold.
)
# out: attention output [B, T, H, 128], with the same dtype/device as q.

    CuTe DSL is imported lazily, so the first eligible call compiles the matching SM90 or SM100 kernel for the input device.

    Exact KV sink¶

    Any contiguous valid key/value range can be kept exact. For a text prefix:

    out = sol_attn(
    q,
    k,
    v,
    tau=1.0,
    sink_start=0,
    sink_tokens=valid_text_tokens,
)

    For a text suffix, omit sink_start:

    out = sol_attn(
    q,
    k,
    v,
    tau=1.0,
    sink_tokens=valid_text_tokens,
)

    Exactness is applied at 64-token KV-block granularity. In an MMDiT integration, the sink keeps valid text K/V blocks exact; valid text-query rows still use dense attention, while Sol-Attn serves image or video query rows.

    Split KV on H100¶

    H100 supports kv_splits=1, 2, and 4; B200 currently uses kv_splits=1.

    out = sol_attn(q, k, v, tau=1.0, kv_splits=4)

    The model integration layer can select split 4 automatically for SM90 sequences of at least 65,536 tokens and split 1 otherwise.

    Sol-Engine integration¶

    Sol-Engine provides:

    • ordinary self-attention dispatch through sol_attn_attention;
    • MMDiT dispatch through sol_attn_hunyuan;
    • dense fallback and architecture-aware split selection;
    • right-padding handling, exact text K/V sinks, and dense text queries;
    • lightweight runtime counters for end-to-end validation.

    Set SOL_ATTN_STRICT=1 during validation to raise kernel or integration errors instead of silently falling back to dense attention.
