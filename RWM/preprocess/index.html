Canonical contract

  • T_A_B 把 B 坐标映射到 A；列向量。T_W_E=T_W_raw @ T_raw_E，T_C_E=inverse(T_W_C) @ T_W_E。
  • Canonical E：+X physical approach，+Z signed jaw，+Y=+Z×+X。桌面参考下两侧 +Z 都指观察者左；XYZ 固定红/绿/蓝。
  • OpenCV C：+X image-right，+Y image-down，+Z optical-forward。Keypoint-derived Human 通常使用 virtual jaw center；Robot 保留已识别的 flange/link/TCP origin，未知 offset 不猜。
  • Gripper：0=open, 1=closed；按 dataset/version 固定 endpoints、outlier envelope 和 mask。

Canonical Robot80 and the shared80 profile interface

Frozen canonical sidecar 不重打包：它继续在 slots 58:67 保存逐帧 camera pose / incoming ego-motion，用于审计以及未来 camera conditioning。Qwen-style 选择发生在 dataset/model 消费边界：model-facing state/action mask 只开放 dataset spec 声明的 34/17/20 slots， camera 值保留在 raw canonical fields 中但不进入当前模型。

每个 dataset 使用 strict complete-profile eligibility，并对 TI2V、forward、inverse、policy 共用同一 clean-span policy：state row 只有在所有 required state masks 全 true 时才 eligible； incoming edge 只有在两端 state eligible、time/continuity 有效且所有 required motion masks 全 true 时才连接。任一 required slot=false 都会切断 span。Window [s,e) 只要求 内部 motion80[s+1:e]；row 0 和每个 span 首帧不消费其窗口外 incoming motion。 

canonical state80[t]  = observed absolute robot state + absolute T_W_C[t]
canonical motion80[t] = incoming robot transition + incoming camera ego-motion
model initial state   = canonical state row 0, masked to the dataset profile
model action80        = canonical motion rows 1:F, masked to the same profile
command80[t] = t 时刻真实下发的 command；provenance 不可靠则 mask=false

Current model 不消费 camera slots；T_W_C 继续作为独立 sidecar tensor 提供给未来 CaPE/其他路径。

本项目继续保留既定的 state-derived motion80 语义：joint 是 observed delta，EEF 是 camera-frame observed delta，gripper 是 target-row observed closedness g[t]。这里的 “Qwen-style” 仅指 80-D arm template、逐维 mask 和 model-facing camera geometry 与 robot action 分离；它不把本项目改成 Qwen 报告中的 absolute joint action 或 3-D rotation-vector action。

令 s=t-1。State EEF 使用 T_Ct_Et=inverse(T_W_C[t]) @ T_W_E[t]。Motion translation 使用 Δp_Cs=R_Cs_W @ (p_W_E[t]-p_W_E[s])；motion rotation 使用 ΔR_Cs=R_Cs_W @ (R_W_E[t] @ R_W_E[s]^T) @ R_W_Cs。 这里的 EEF motion reference frame 指这些 xyz/rotation 数值采用哪一个相机坐标系作为 空间基底，不是视频帧数或 FPS。对当前 human v4 / robot v5 target-row motion80[t]，它表示 t-1→t，因此空间基底是 source camera C[t-1]；旧 v1 把同一条 edge 存在 source row t-1，所以文档中会写成 C[t]。物理 edge 没变，改变的是它存在哪一行。 Canonical camera motion 使用 T_Cs_Ct=inverse(T_W_C[s]) @ T_W_C[t]， 但它的 model-facing mask 为 false。 Column Rot6D 按 [R[:,0], R[:,1]] 存储；下表中的 col0_x 表示第一列在 x 轴上的分量。

State storage frame vs. motion spatial basis

令 s=t-1。不要把“计算 motion 时两个 endpoint 都在 C[s] 下比较”误读成“state80[t] 也存储在 C[s]”。实际存储与 motion basis 是： 

state80[s].eef  = T_Cs_Es
state80[t].eef  = T_Ct_Et                  # target state stays in current camera C[t]
motion80[t].eef = (delta_p_Cs, delta_R_Cs) # incoming edge s→t, expressed in C[s]

求 motion80[t] 时，target endpoint E[t] 会被重表达到 source camera C[s]，再与 E[s] 比较；packed state80[t] 本身仍保持 T_Ct_Et。独立 L1 reconstruction 必须先在 C[s] 内应用 motion： 

p_Cs_Et_pred = p_Cs_Es + delta_p_Cs[t]
R_Cs_Et_pred = delta_R_Cs[t] @ R_Cs_Es
T_Cs_Ct      = inverse(T_W_C[s]) @ T_W_C[t]
T_Ct_Et_pred = inverse(T_Cs_Ct) @ T_Cs_Et_pred

最后才将 T_Ct_Et_pred 与 packed state80[t].eef=T_Ct_Et 比较。只有固定相机 C[s]=C[t] 时，才可直接简写为 state80[t-1] + motion80[t] → state80[t]。Joint motion 是 q[t]-q[s]，不使用 camera basis；gripper 保存 target observation g[t]，不是空间 delta。

VideoAction cache discovery

SanaVideoActionDataset 接受 data_dir={dataset_name: dataroot}，逐 dataroot 统计 chunks/*.zip 并结合 dataset-local _model_fps 与最短 multi-FPS tier 推导 cache 名，再从统一 json_cache_dir 加载。新 cache 使用 _videoaction 与旧 Sana cache 隔离： 

<Dataset>-<zip_count>_model_fps_<min>-<max>_f<frames>_videoaction_cached_dataset.json
<same-stem>_cache_summary.json
<same-stem>_normalization_stats.json

dev/rwm/tools/filter_videoaction_into_json.py 使用 dev/rwm/configs/videoaction_filter_config.json 批量构建六个 dataset。 工具只读 canonical values/masks；所有 summary 保持 alignment_status=UNVERIFIED、training_ready=false。 AgiBotWorld-Beta 的空、缺失、类型错误或越界 action_config 属于 episode-local FILTER defect：整 episode 会按稳定 reason 显式 DROP，记录 source/canonical locator 和错误详情，并继续完整 corpus accounting；不会截断或回退成 full_episode。Canonical checksum/schema/converter、source join/member、row/time identity、worker accounting 和 I/O 错误仍 fail closed。 Dataset 默认生成 Embodiment: <dataset-spec description>. Instruction: <cache prompt> 作为 model-facing text condition。YAML 设置 data.embodiment_type_only=true 时只返回 Embodiment: <dataset-spec description>.。该开关不修改 cache、canonical values 或 masks。

当 sort_dataset=false 且 shuffle_dataset=false 时，多 dataset loader 先按 exact source zip_file 稳定分组，再按各 dataset 的 normalized ZIP position (zip_index+0.5)/eligible_zip_count 做无随机数的确定性归并； 并列时使用 YAML dataset 顺序。该实现只调度 ZIP，不按 ZIP 内 item 数加权；每个 ZIP 出现一次且内部 item 相对顺序不变。现有 rank/window 逻辑不变， 因此 rank 边界仍可能切开 ZIP。

训练时钟只由 dataset spec 决定：AgiBotWorld-Beta/AgiBotWorld2026 固定 model_fps=30，DROID 与三个 human-action dataset 固定 model_fps=16。Cache 不要求 canonical 自报的历史 model_fps 与该训练时钟相等；后者只作为 audit metadata 保留，不参与 cache tier 或 mRoPE。

每个 episode 必须 exact join authoritative source episodes/chunks manifest；human-v4 selected meta/data/video/sidecar 还要通过 checksum ledger 的 ZIP size/CRC receipt，dataset decode 前再次核验 selected-video receipt。AgiBotWorld2026、DROID、EgoVerse 当前 READY.json 不绑定 canonical manifest/checksum hash，因此 cache identity 显式写入 canonical_artifact_receipt_binds_manifest=false，且不得提升 training_ready。
