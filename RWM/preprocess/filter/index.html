FILTER Evidence

这里记录 frozen canonical sidecar 下游的数据质量研究。每个 Qwen-style S* stage 和后续 C* stage 使用独立页面；每页先定义可迁移到任意 robot dataset 的 General Requirements，再记录 dataset-specific profile、exact run 结果和限制。

Claim boundary：当前模式是 FILTER / Evidence，不是 corpus-strict selection。所有 canonical values、transforms、timestamps 和 masks 都是只读输入；当前没有 KEEP/DROP/REVIEW manifest、named-loss eligibility 或 L4 training_ready 结论。发现 source meaning、frame、time 或 packing 问题时必须返回 ALIGN，不能在 FILTER 内修复。

跨数据集复用合同

General stage contract（本组文档）
  → dataset/source profile（field mapping、units、frames、time、model、policy）
  → exact run evidence（input hashes、coverage、metrics、flags、failures）
  → separately frozen named-loss selection / eligibility

以后接入 DROID、AgiBotWorld2026 或其他 robot data 时，只新增/版本化 dataset profile 与 run evidence；不能复制 Beta 的 field 数量、matrix、URDF、FPS、threshold 或 verdict 作为默认值。

Shared requirementRequired for every S/C run
Exact identity所有 FILTER-stage S/C run 绑定 immutable source revision、canonical sidecar、schema/converter、ALIGN receipt、policy、code 和 hashes；hash/schema drift 为 INPUT_REJECTED，不能 fallback 到“最相近”的 profile。S4 source-FK 与 S5 等 ALIGN-owned oracle/gate 可发生在 final receipt 之前，但必须绑定 exact source/model/transform inputs，并把产物纳入后续 receipt；不能形成“先有 receipt 才能生成 L2”的循环。
Dataset profile声明 dataset、embodiment/robot model、side/entity、tool/mount/hardware、camera role、control mode、FPS/time regime；每个 signal 记录 producer、semantic view、field/slot、frame/basis、origin、representation、units 与 canonical mask。
Four scopesMeasurement unit、aggregation unit、selection unit 与 named training loss 必须分开。Row/transition evidence 可以汇总到 range/split/episode，但不能自动变成整段 DROP。
Statesartifact_status、alignment_status、measurement flag、selection_status、eligibility 与 training_ready 分开表达；生成文件成功、没有 flag 或高 retention 都不是 alignment/readiness PASS。

统一的 per-ZIP filter sidecar 格式

Project decision — 2026-07-08：以后所有 corpus filter 都按 canonical ZIP 独立写 sidecar。若输入为 canonical/chunks/00000100.zip，名为 urdf_align 的 filter 写 canonical/chunks/00000100_urdf_align.json；其他 filter 只替换文件名后缀。文件名已经表达 ZIP 与 filter，JSON 不再增加 zip/filter/problem_episodes 外层。

{
  "episode_97000000": {
    "num_anomalies": 1,
    "anomalies": [
      {
        "row_idx": 153,
        "frame_idx": 153,
        "bad_sides": ["left", "right"],
        "left": {"position_error_m": 0.224, "rotation_error_deg": 0.0012},
        "right": {"position_error_m": 0.224, "rotation_error_deg": 0.0011}
      }
    ],
    "position_threshold_m": 0.001,
    "rotation_threshold_deg": 0.1
  }
}
  • 顶层 key 必须来自 canonical manifest 的 exact episode member prefix；不得从 ZIP 编号推导 source chunk，也不得重新格式化 episode identity。
  • 顶层覆盖该 canonical ZIP 的全部 episode。正常 episode 显式写空结果；读取/计算失败显式写 error，不能通过缺 key 冒充正常。
  • 每个 filter 只写自身 metric、异常 frame 与实测值，不读取其他 filter 的决定，不修改 canonical values/masks，也不在此阶段生成 clean span。
  • 所有 filter 完成后，由单独的 aggregation step 按 (canonical ZIP, episode key, frame_idx) 合并 flags，并且只在该步骤统一计算异常区间、transition/window eligibility 与 clean spans。

稳定边界

frozen canonical + exact release/checksum identity
  → split view: state/frame [s,e), internal motion [s+1,e)
  → S*/C* numeric evidence and reason ranges
  → policy review and labeled examples
  → only later: named-loss KEEP/DROP/REVIEW + eligibility
  → corpus-strict only: optional L4 readiness
  • motion80[t] 是 observed [t-1]→[t]，不是 issued command；不能据此伪造 command-state filter。
  • 任一 stage 的 flag 都是 evidence，不是坏数据概率，也不是整 split/episode 的删除指令。
  • 阈值、代码、sidecar、task annotation、policy 和输出都必须用 exact hash 绑定；input drift 必须 fail closed。
  • 当前 10-long pilot 用于发现算法和阈值问题，不能外推为 full-corpus retention 或 readiness。
