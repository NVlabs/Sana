RGB-only 手部锚点标注规范 v1

适用范围：只用于 blinded detector-calibration RGB packet。标注者和 reviewer 只能看 packet 内的原始 RGB 与人工点击；禁止查看或使用 MediaPipe、RTMPose、HaWoR/MANO、source projection、K/3D、camera-ray、residual 或 audit/heldout 结果。

机器可读权威版本是 configs/preprocess/egocentric_annotation/egodex_rgb2d_manual_annotation_rubric_v1.json，packet manifest 与 preparation receipt 必须绑定它的 exact path/hash/content。本文是同一 contract 的人工说明，不增加未绑定规则。

1. Side 与 hand row

字段冻结定义
left/right佩戴者/人的解剖学左手、右手，不是画面左侧/右侧。不能从当前 RGB 确定时填 unknown，不得猜。
Hand 1 / Hand 2只是当前帧的无序 UI slot；不编码左右、画面位置或跨帧 track identity。
建立 hand row只要 RGB 中能辨认出一只手的任何像素，就建立 hand row；即使四个目标点都不可定位，也保留该 row 并把四点全部设为 not_visible。
no_visible_hands=true仅当整帧没有任何可归因于手的可见像素时使用。不能用它回避 side、遮挡或点位不确定性。

2. 四个锚点

锚点点击位置
wrist0手掌与前臂交界处、可见腕关节/腕横纹的中心。
thumb_tip4拇指最远端可见指尖轮廓的中心，不点甲面或指腹内部。
index_tip8食指最远端可见指尖轮廓的中心。
middle_tip12中指最远端可见指尖轮廓的中心。

只有能从当前 RGB 直接定位并满足冻结 reviewer tolerance 的点才标 visible；否则标 not_visible 且 x/y=null。禁止根据遮挡后走向、相邻帧、另一只手或任何模型输出外推位置。

3. Visibility 与 occlusion

值定义
fully_visible完整手部和四个目标区域都清楚可见。
partially_visible手可见，但至少一个区域被遮挡、出框或无法定位。
uncertain仅凭 RGB 无法在不猜测的情况下判断 full/partial。
none目标区域没有实质遮挡。
self同一只手或其手臂遮挡目标。
object物体或场景遮挡目标。
other_hand另一只手遮挡目标。
out_of_frame目标位于 RGB 边界之外。
multiple以上两个或更多原因同时实质影响。
unknown仅凭 RGB 无法判断遮挡原因。

4. Reviewer gate

  • Reviewer 必须是不同真实人员，导入已冻结的 canonical draft，仅使用 Review mode，不修改 annotation content。
  • 原始 1920×1080 坐标下，冻结 visual tolerance 为 wrist0 ≤12 px，thumb/index/middle fingertip 各≤8 px Euclidean distance；UI zoom 不改变这些阈值。
  • APPROVED：side、hand row、visibility、occlusion 与全部可见点符合本规范，且 marker 落在 tolerance 内。
  • NEEDS_REVISION：画面可标，但任一内容应由 annotator 改正；本轮不能 finalize，必须新建 versioned handoff。
  • REJECTED：该 row 无法在本规范下接受。Reviewer 不自行“修点”或平均点位。

5. 操作前/交付检查

  1. 运行 calibration-only verify-packet；确认 237/237 frame、rubric descriptor、pixel identity 和 read-only inventory PASS。
  2. 在受控账号/节点上以 loopback server + approved SSH tunnel 提供 UI；不要在共享节点长期运行无认证 server，也不要绑定 0.0.0.0。
  3. 标注者使用一个预先分配的 stable ID；reviewer 使用另一个 stable ID。工具只验证两个 declared IDs 不同，真实自然人身份与文件传输由外部流程证明。
  4. 每帧图片必须成功加载后才能标注/审批；图片加载失败、mixed IDs、未完成 rows 或错误 packet/rubric hash 都不得 final export。
  5. 保留 exact draft/reviewed/final bytes、SHA-256、安全传输记录和 handoff receipts；浏览器 localStorage 仅作恢复，不能代替导出文件。

Claim boundary：packet verification 或 manual schema PASS 都不等于 detector policy PASS、camera/hand alignment、L0–L3、FILTER 或 training readiness。只有 approved manual 后，才允许按已冻结 thresholds 运行 calibration evaluator 与 source-ray reducer。
